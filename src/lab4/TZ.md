### 4.1. Задача 1: рекомендация фильмов (ООП)

Файлы данных:
- `data/movies.txt`: на строке `id,название`;
- `data/history.txt`: на строке id фильмов одного пользователя через запятую.

Если файлов нет, создай их из примера и отметь это в `STATUS.md`:

```
# movies.txt
1,Мстители: Финал
2,Хатико
3,Дюна
4,Унесенные призраками

# history.txt
2,1,3
1,4,3
2,2,2,2,2,3
```

Список просмотров текущего пользователя вводится одной строкой в stdin (`2,4`), название рекомендованного фильма печатается в stdout. Для примера ввод `2,4` даёт `Дюна`.

**Алгоритм (не изменять):**
1. Из историй по всем пользователям выбираются те, у которых хотя бы половина фильмов совпадает с заданной (то есть пользователи, посмотревшие минимум половину фильмов того, для кого формируется рекомендация).
2. Из отобранных списков исключаются все фильмы, которые пользователь уже посмотрел.
3. Для оставшегося списка фильмов подсчитывается суммарное количество просмотров среди всех пользователей сервиса, и фильм с максимальным числом просмотров выбирается как рекомендация (если таких несколько, выбирается любой).

| Вопрос | Решение |
|---|---|
| «Хотя бы половина» | Считаем по множествам разных id: `common = len(watched & films)`, история отобрана, если `2 * common >= len(watched)` |
| «Оставшийся список фильмов» | Объединение фильмов отобранных историй за вычетом `watched` (множество кандидатов) |
| Область подсчёта в шаге 3 | Буквально по условию: просмотры считаются **по всем историям сервиса**, а не только по отобранным. Счётчик строится один раз при загрузке |
| Дубли в истории (`2,2,2`) | Каждое вхождение id считается отдельным просмотром |
| Ничья | Берётся фильм с наименьшим id (условие разрешает любой, нужна детерминированность) |
| Кандидатов нет | stdout: `Рекомендаций нет`, код 0 |
| Ввод пользователя | Id через запятую, пробелы допустимы, повторы схлопываются. Пустая строка (или конец ввода), нецелое, id вне каталога: сообщение в stderr, код 1 |
| Ошибки в файлах | `ValueError` с именем файла и номером строки (плохой id, нет запятой, пустой элемент, повторный id в каталоге, id истории отсутствует в каталоге). Пустые строки пропускаются. `main` ловит `ValueError` и `OSError`, пишет в stderr, возвращает 1 |
| Название с запятой | В `movies.txt` делим по **первой** запятой |
| Язык | Python, «System.out» из условия означает `stdout` |

Эталон логики (структуру менять можно, смысл нет):

```python
candidates: set[int] = set()
for counts in history.film_counts:               # Counter id -> число вхождений, по одному на пользователя
    common = len(watched & counts.keys())
    if 2 * common >= len(watched):
        candidates |= counts.keys() - watched
if not candidates:
    return None
score = {m: history.views[m] for m in candidates}   # views: Counter по ВСЕМ строкам истории
best = max(candidates, key=lambda m: (score[m], -m))
return catalog.get(best)
```

### 4.2. Усложнение с весами: режим `--weighted`

Из условия: чем больше общих фильмов, тем больше вес рекомендации (половина совпала: 0.5, 70%: 0.7, все: 1).

Запуск: `python -m recommender.app --weighted`. Без флага работает §4.1, результат не меняется. Шаги 1 и 2 в обоих режимах одинаковы. В режиме весов меняется только подсчёт в шаге 3.

| Вопрос | Решение |
|---|---|
| Вес истории | `w(h) = common(h) / len(watched)`, где `common(h) = len(watched & фильмы истории h)` |
| Оценка кандидата | `score(m) = сумма по ВСЕМ историям h от w(h) * (число вхождений m в h)`. Это прямое обобщение шага 3: в обычном режиме вес каждого просмотра равен 1 |
| Без `float` | `len(watched)` одинаково для всех историй, поэтому порядок оценок не меняется, если считать `score(m) = сумма common(h) * вхождения`. Деление не нужно, всё в целых числах |
| Ничья | Наименьший id, как в обычном режиме |
| Вывод | Только название фильма (или `Рекомендаций нет`), формат не меняется |
| Аргументы | Допустимы `[]` и `["--weighted"]`. Любые другие: сообщение об использовании в stderr, код 1. `argparse` не используй |

Проверочный сценарий, в котором режимы дают разный ответ (обязателен в тестах). Каталог из 4 фильмов (id 1–4), истории `1,2,3` / `1,4` / `1,4`, ввод `1,2`:
- обычный режим: просмотры 3→1, 4→2, ответ фильм 4;
- режим весов: оценка 3 = 2×1 = 2, оценка 4 = 1+1 = 2, ничья, ответ фильм 3 (наименьший id).

В паспорте покажи, где одной строкой переключается альтернатива «считать только по отобранным историям».

### 4.3. Задача 2: разбивка респондентов по возрастным группам

Аргументы командной строки: границы групп, например `18 25 35 45 60 80 100`. Группы: 0–18, 19–25, 26–35, 36–45, 46–60, 61–80, 81–100, 101 и старше. Ввод: строки `<ФИО>,<возраст>`, строка `END` завершает список. Вывод: строки `<Группа>: ФИО (возраст), ФИО (возраст), …`.

Правила вывода: группы от старшей к младшей; в группе сортировка по возрасту по убыванию, при равном возрасте по ФИО по возрастанию; пустые группы не выводятся.

Пример (в PDF приведён только вывод, входные данные составлены по нему). Границы `18 25 35 45 60 80 100`:

```
Ввод (порядок произвольный):
Ярилова Розалия Трофимовна,29
Егоров Алан Петрович,7
Кошельков Захар Брониславович,105
Иванов Варлам Якунович,88
Старостин Ростислав Ермолаевич,50
Соколов Андрей Сергеевич,15
Дьячков Нисон Иринеевич,88
END

Вывод:
101+: Кошельков Захар Брониславович (105)
81-100: Дьячков Нисон Иринеевич (88), Иванов Варлам Якунович (88)
46-60: Старостин Ростислав Ермолаевич (50)
26-35: Ярилова Розалия Трофимовна (29)
0-18: Соколов Андрей Сергеевич (15), Егоров Алан Петрович (7)
```

| Вопрос | Решение |
|---|---|
| Метки групп | Первая `0-b0`, средние `b(i-1)+1-b(i)`, последняя `b(last)+1` + `+` (то есть `101+`). Возраст, равный границе, входит в нижнюю группу (18 → `0-18`) |
| Допустимые границы | Хотя бы одна, целые, ≥ 0, строго возрастают. Иначе сообщение об использовании в stderr, код 1 |
| Поиск группы | `bisect.bisect_left(bounds, age)`, O(log k) |
| Структура данных | Один раз отсортировать всех по ключу `(-age, name)`. Индекс группы при таком порядке не возрастает, поэтому `itertools.groupby` по индексу группы выдаёт группы сразу от старшей к младшей, а внутри каждой порядок уже правильный. Итого O(n log n), без словарей и повторных сортировок |
| Сравнение ФИО | Обычное сравнение строк Python (по кодам символов), без `locale` |
| Возраст выше 123 | Принимается без ошибки и попадает в последнюю группу (условие позволяет считать, что таких нет) |
| Плохая строка (нет запятой, возраст не целое или < 0, пустое ФИО) | Предупреждение в stderr с номером строки, строка пропускается, работа продолжается, код 0 |
| Разбор строки | Делим по **последней** запятой, ФИО и возраст `strip()` |
| `END` | Сравнивается после `strip()`, регистр важен. Строки после `END` игнорируются. Конец ввода без `END` тоже завершает список. Пустые строки пропускаются |
| Респондентов нет | Вывод пуст, код 0 |

## 6. Документирование кода

Язык docstring русский, имена в коде английские. Комментарии `#` только там, где нужно объяснить «почему», не «что».

**Модуль:** docstring в начале каждого `.py` (включая `__init__.py`): назначение, какие классы и функции содержит, пример запуска для `app.py`.

**Класс:** краткое описание, секция `Атрибуты:` (для dataclass обязательно), инварианты, если есть.

**Функция и метод** (публичные и приватные; исключены только dunder-методы и вложенные функции): первая строка до 100 символов, заканчивается точкой, повелительного вида не требуется. Дальше секции в таком порядке, если они применимы:

```python
def index_of(self, age: int) -> int:
    """Возвращает номер возрастной группы для заданного возраста.

    Аргументы:
        age: возраст в годах, целое число не меньше 0.

    Возвращает:
        Индекс группы: 0 для самой младшей, len(bounds) для самой старшей.

    Исключения:
        ValueError: если age отрицательный.

    Пример:
        >>> AgeGroups([18, 25]).index_of(18)
        0
    """
```

Правила:
- `Аргументы:` обязательна, если есть параметры кроме `self`/`cls`. `Возвращает:` обязательна, если функция возвращает не `None`. `Исключения:` обязательна, если в теле есть `raise`.
- Все параметры и возвращаемые значения снабжены аннотациями типов.
- `Пример:` с `>>>` обязателен у: `MovieCatalog.from_lines`, `parse_watched`, `Recommender.recommend`, `AgeGroups.index_of`, `AgeGroups.split`, `parse_bounds`, `parse_respondent`, `format_group`. Примеры выполняются как doctest (§8.1) и не должны зависеть от файлов.
- Для `tools/*.py`: модульный docstring и однострочные docstring у функций (секции не обязательны).
- README: назначение, запуск (оба приложения, режим `--weighted`), примеры ввода-вывода, структура проекта, принятые решения (таблицы §4 и свои), как запускать тесты и проверку, как пересобрать PDF и заполнить `docs/meta.json`.

## 7. Тестирование

Цель: **100% покрытия строк и ветвей двух пакетов при минимальном числе тестовых функций.** Ориентир 6–8, потолок 10.

1. `pytest.ini`: `testpaths = tests`, `addopts = --cov=recommender --cov=age_groups --cov-branch --cov-report=term-missing`. `.coveragerc`: `[report] exclude_lines = if __name__ == .__main__.:` и `fail_under = 100`. `tools/` в покрытие не входит.
2. Без `parametrize`: он раздувает счётчик «N passed». Используй таблицы случаев и цикл внутри одной тестовой функции, а в каждом `assert` пиши сообщение с именем случая: `assert actual == expected, case_name`.
3. Основная экономия идёт за счёт сквозных тестов: `main(...)` с `io.StringIO` покрывает разбор ввода, загрузку, алгоритм и вывод за один вызов. Отдельные функции тестируй напрямую только ради крайних случаев.
4. Файловый ввод-вывод проверяется одним тестом с `tmp_path`: в нём же прогоняются оба режима (обычный и `--weighted`) на проверочном сценарии §4.2. Остальное идёт через `from_lines` и `StringIO`.
5. Каждый тест содержит осмысленные `assert` на результат (вывод, код возврата, содержимое структуры). Тест, который только вызывает функцию ради строки покрытия, запрещён. Порядок запуска не важен, общего состояния нет, проверок по времени нет.
6. Сообщения об ошибках проверяй по характерному фрагменту, а не по полному тексту. Допустимы только фикстуры `tmp_path` и `io.StringIO`, без моков.
7. `# pragma: no cover` в коде запрещён.

Обязательные проверки поведения (при сжатии их можно объединять в таблицы, но не терять):
- **Задача 1:** пример `2,4` → `Дюна`; граница «ровно половина» (отобрана) и «меньше половины» (нет); просмотренные фильмы не попадают в рекомендацию; ничья → наименьший id; дубли в истории считаются отдельными просмотрами; просмотры считаются по всем историям, а не только по отобранным; нет кандидатов → `Рекомендаций нет`; сценарий §4.2 в обоих режимах (ответы 4 и 3); неверные аргументы командной строки; ошибки пользовательского ввода; все ошибки файлов из §4.1; пустые строки пропускаются.
- **Задача 2:** пример §4.3 через `main`; возрасты 0, 18, 19, 100, 101, 123 попадают в свои группы; ничья по возрасту решается по ФИО; пустые группы не выводятся; все варианты плохих границ; плохая строка пропускается с предупреждением; `END` в середине ввода и конец ввода без `END`; пустой ввод.

**Проверка осмысленности — мутации** (§8.2): 100% покрытия не доказывает качество тестов, поэтому `tools/mutations.py` автоматически вносит 6 поломок. Тесты обязаны каждую поймать. Выжившую мутацию убивай дополнительным случаем в существующей таблице, а не новой функцией.

| № | Мутация | Ожидаемо ломает |
|---|---|---|
| 1 | `>=` → `>` в проверке половины | граница «ровно половина» |
| 2 | убрать `- watched` | исключение просмотренных |
| 3 | убрать `-m` из ключа `max` | ничья |
| 4 | убрать множитель `common` в оценке режима весов | сценарий §4.2 |
| 5 | `bisect_left` → `bisect_right` | границы групп (18, 25, 100) |
| 6 | убрать `name` из ключа сортировки | ничья по возрасту |

**Минимизация:** после 100% посмотри, какие тесты можно слить. Объединяй, не удаляя проверки из списка обязательных.

## 8. Инструменты проверки

### 8.1. `tools/check.py`: единая проверка

`python tools/check.py` завершается кодом 0, только если всё проходит. Этапы по порядку, каждый печатает одну строку `OK`/`FAIL` с причиной:

| Этап | Что проверяет |
|---|---|
| lint | AST-проверки по §6 для пакетов (модульные docstring, docstring у функций и классов, первая строка до 100 символов и с точкой, секции `Аргументы:`/`Возвращает:`/`Исключения:`, аннотации, обязательные `>>>`), длина строк ≤ 100 во всех `.py`; отсутствие `float` в `recommender/`; число функций `def test_` в `tests/` ≤ 10; нет `parametrize` и `pragma: no cover` |
| tests | `pytest` с покрытием, выход 0 при покрытии 100% строк и ветвей (`fail_under`) |
| doctest | `doctest.testmod` для каждого модуля обоих пакетов |
| smoke | Запуск настоящих CLI через `subprocess` и сверка вывода побайтово: задача 1 в обоих режимах на `2,4` (ожидается `Дюна`), пример §4.3, плохой ввод даёт код 1 и пустой stdout. Для задачи 1 данные берутся из `build/example/data/`, куда `check.py` записывает пример §4.1, процесс запускается с `cwd=build/example` и `PYTHONPATH` на корень проекта. Так проверка не зависит от файлов в `data/` |
| mutations | только с `--mutations` или `--all` (§8.2) |
| docs | только с `--docs` или `--all` (§8.4) |

После этапов tests/smoke `check.py` записывает `build/facts.json` (§8.3). Флаг `--all` включает все этапы и обязателен для финальной проверки. Этапы по мере готовности добавляются в итерациях (§9).

### 8.2. `tools/mutations.py`

Содержит список `MUTATIONS`: для каждой мутации номер, файл, точная исходная подстрока `old`, замена `new`, описание. Запуск для каждой: копия проекта (без `.venv`, `build`, `.git`) в `build/mutants/<N>/`, подстановка (`old` должна встретиться в файле ровно один раз, иначе ошибка), запуск `python -m pytest -x -q --no-cov -p no:cacheprovider`. Мутация считается **убитой**, если код возврата pytest равен 1 (упал тест). Коды 2 и выше значат, что мутация сломала сборку, и это ошибка таблицы. Рабочее дерево не изменяется. Итог (убитые, упавший тест, описание) пишется в `build/mutations.json`. Все 6 должны быть убиты.

### 8.3. `build/facts.json` и переменные документов

В Markdown-исходниках документов числа и вывод запрещено писать вручную. Пиши плейсхолдеры `{{имя}}`, сборщик подставляет значения. Неизвестный плейсхолдер или оставшийся `{{` — ошибка сборки.

| Переменная | Значение |
|---|---|
| `python_version`, `os_name`, `date_ru` | версия Python, ОС, дата сборки по-русски («14 ноября 2026», без зависимости от локали) |
| `tests_functions`, `tests_passed` | число функций `def test_` и «N passed» из pytest |
| `cov_percent`, `cov_statements`, `cov_branches` | итоговое покрытие, число операторов и ветвей |
| `coverage_table` | Markdown-таблица покрытия по файлам |
| `mutations_total`, `mutations_killed`, `mutation_table` | итог и таблица мутаций (№, что изменено, результат, какой тест упал) |
| `tree` | дерево проекта без `.venv`, `build`, `.git`, `__pycache__` |
| `pytest_tail` | последние строки вывода pytest с таблицей покрытия |
| `smoke_movies`, `smoke_movies_weighted`, `smoke_groups` | блоки «команда, ввод, фактический вывод» |
| `student_line` | строка «Студент: …, группа …» из `docs/meta.json`, пустая, если поля пусты |

Можно добавлять свои переменные, зарегистрировав их в `check.py`.

### 8.4. `tools/build_docs.py`

Читает `docs/src/*.md` и `build/facts.json`, собирает `docs/report.pdf`, `docs/elevator_pitch.pdf`, `docs/tech_passport.pdf`, `docs/cheatsheet.pdf` и проверяет результат. Вёрстка на `reportlab` по стилю из §10.0.

Поддерживаемое подмножество Markdown (держи исходники в нём): один заголовок `#` (название документа), сразу под ним строка `>` (подзаголовок), `##` и `###`, абзацы, списки `-` и `1.` одного уровня, таблицы, блоки кода в тройных кавычках, **жирный**, *курсив*, `код` в строке, `---` на отдельной строке как разрыв страницы. Экранируй `<`, `>`, `&` в тексте и коде (для reportlab это XML).

Проверки после сборки (ошибка, если не выполнены):
- число страниц: pitch ровно 2, report 2–3, остальные без лимита;
- `{{` отсутствует в исходниках после подстановки;
- каждый символ текста есть в cmap подключённого шрифта (в ReportLab `pdfmetrics.getFont(name).face.charToGlyph`); если нет, замени символ;
- извлечённый текст (`pymupdf`) содержит ключевые русские слова документа и не содержит `(cid:`, `�`, `TODO`, `FIXME`;
- строки в блоках кода не длиннее 95 символов (иначе обрезка);
- ссылки на код в формате `` `путь.py:Имя` `` или `` `путь.py:Класс.метод` `` (используются в шпаргалке и паспорте) указывают на существующие определения (проверка по AST);
- каждая страница отрендерена в `build/png/<документ>-<N>.png` (150 dpi) для визуального просмотра.

После сборки **открой PNG каждой страницы инструментом чтения изображений и посмотри**: кириллица без квадратов, таблицы не обрезаны, код читаем, нет пустых страниц и одиноких заголовков внизу. Найденное исправляй и пересобирай. Автоматические проверки этого не заменяют.

### 10.4. `docs/cheatsheet.pdf`: шпаргалка «Вопросы преподавателя по коду»

30–40 пар. Каждая группа `##` — таблица из столбцов «Вопрос» / «Ответ» (1–3 предложения) / «Где в коде и как показать». Ссылки на код в формате `` `путь.py:Имя` `` (проверяются автоматически), рядом команда или строка для демонстрации. Группы:
1. ООП и архитектура: зачем классы, `frozen dataclass`, композиция вместо наследования, `classmethod` `from_file`, зачем `main` принимает потоки.
2. Алгоритм рекомендаций: каждый шаг, почему множества, зачем `Counter`, сложность, ничья, пустой ввод, дубли, как поменять порог «половины», как работает режим весов.
3. Структуры второй задачи: `bisect_left` и `bisect_right`, почему `groupby` требует отсортированного ввода, ключ `(-age, name)`, устойчивость сортировки, сложность, порядок букв `ё`, почему не словарь.
4. Python: `with open(..., encoding=...)`, аннотации, `if __name__ == "__main__"`, исключения и `ValueError`, подстановка `StringIO`, `sys.argv`, docstring и doctest.
5. Тесты: покрытие ветвей, почему 100% не гарантирует корректность, мутации, почему тестов мало и нет `parametrize`, как запустить.
6. Каверзные: огромный файл, почему не `float` для «половины», два фильма с равным счётом, почему в режиме весов не нужно делить, что если вес считать только по отобранным историям.
