# Elevator pitch
> Рекомендации фильмов и возрастные группы · {{date_ru}}

## За 30 секунд

Это две маленькие консольные программы на Python. Первая советует фильм: находит людей с похожими вкусами и берёт самый популярный фильм, которого ты ещё не видел. Вторая раскладывает участников опроса по возрастным группам и печатает их от старших к младшим. Обе написаны на классах, читают stdin и пишут stdout, поэтому их легко тестировать целиком, подставляя вместо консоли строки.

## Речь на 2 минуты

Я сделал две программы. Первая рекомендует фильм. На входе каталог фильмов, история просмотров всех пользователей и строка с тем, что посмотрел я, например «2,4». Алгоритм из условия я реализовал ровно по шагам. Сначала отбираю пользователей, которые видели хотя бы половину моих фильмов. «Половину» проверяю в целых числах: удвоенное число общих фильмов не меньше числа моих фильмов. Так нет дробей и ошибок округления. Потом собираю их фильмы, кроме тех, что я уже видел. Из этих кандидатов выбираю тот, у которого больше всего просмотров по всему сервису. Если таких несколько, беру фильм с меньшим id, чтобы ответ был всегда одинаковым. Для примера «2,4» программа печатает «Дюна».

Усложнение с весами включается флагом --weighted. В нём пользователь, совпавший со мной сильнее, влияет на выбор больше. Деление на число моих фильмов одинаково для всех, поэтому я его просто опускаю и считаю всё в целых числах.

Вторая программа делит респондентов на возрастные группы по границам из командной строки. Группу ищу двоичным поиском. Всех людей сортирую один раз: по убыванию возраста, при равенстве по ФИО. После такой сортировки группы уже идут от старшей к младшей, и groupby просто нарезает список на куски.

Отдельно я продумал плохой ввод. Если в файле с фильмами ошибка, программа называет файл и номер строки и завершается с кодом 1, без трассировки Python. Плохую строку респондента вторая программа пропускает, предупреждает об этом в stderr и продолжает работу.

Код разбит на классы с одной обязанностью каждый, у всех функций есть docstring с примерами. Тесты покрывают все строки и ветви. Отдельный скрипт специально ломает код в {{mutations_total}} местах и проверяет, что тесты это замечают.

## Четыре самых тонких места

1. **«Хотя бы половина».** Считаются разные общие фильмы, и условие `2 * common >= len(watched)` записано в коде один раз. При двух моих фильмах хватает одного общего.
2. **Просмотры по всем историям.** В шаге 3 условие говорит «среди всех пользователей сервиса», поэтому счётчик общий для всего сервиса, а не только для похожих людей. Отобранные истории решают, *кто* кандидат, а весь сервис решает, *кто* из них лучше.
3. **Что меняет --weighted.** Только шаг 3: просмотр в истории считается с весом, равным числу общих с тобой фильмов. На примере из тестов обычный режим выбирает фильм 4, режим весов фильм 3.
4. **Почему sort + groupby работает.** После сортировки по `(-age, name)` номер группы только убывает, значит люди одной группы стоят подряд. `groupby` склеивает только соседей, поэтому без сортировки он бы ошибся.

## Если спросят «почему тестов так мало»

Тестов мало по числу функций, но не по числу проверок. Каждая функция прогоняет таблицу случаев, а сквозной вызов `main` с `io.StringIO` проверяет ввод, алгоритм и вывод за раз.
