## 2. Как устроено

### Задача 1: рекомендация фильма

| Класс / функция | Ответственность |
|---|---|
| `recommender/catalog.py:Movie` | неизменяемая запись «id, название» (`frozen dataclass`) |
| `recommender/catalog.py:MovieCatalog` | загрузка `movies.txt`, поиск фильма по id |
| `recommender/history.py:ViewingHistory` | истории пользователей: `Counter` на каждого и общий `Counter` просмотров |
| `recommender/engine.py:Recommender` | алгоритм шагов 1–3 и режим весов |
| `recommender/app.py:main` | аргументы, ввод, вывод, коды возврата |

Алгоритм `Recommender.recommend`:

1. Для каждой истории считается число общих разных фильмов `common`; история отбирается, если `2 * common >= len(watched)` (проверка в целых числах, без деления).
2. Кандидаты: объединение фильмов отобранных историй минус уже просмотренные.
3. Каждому кандидату сопоставляется число просмотров по **всем** историям сервиса (счётчик строится один раз при загрузке).
4. Побеждает кандидат с наибольшим числом просмотров, при равенстве наименьший id; если кандидатов нет, выводится «Рекомендаций нет».
5. В режиме `--weighted` просмотр в истории h весит `common(h)`: это вес `common(h) / len(watched)` из условия, умноженный на общий для всех историй знаменатель, поэтому порядок кандидатов тот же, а дробей нет.

### Задача 2: возрастные группы

| Класс / функция | Ответственность |
|---|---|
| `age_groups/groups.py:Respondent` | неизменяемая запись «ФИО, возраст» |
| `age_groups/groups.py:AgeGroups` | метки групп, поиск группы, разбивка |
| `age_groups/app.py:parse_bounds` | проверка границ из аргументов командной строки |
| `age_groups/app.py:read_respondents` | чтение строк до `END`, пропуск плохих строк с предупреждением |
| `age_groups/app.py:format_group` | строка вывода «Группа: ФИО (возраст), …» |

Выбор структур данных:

- группа ищется через `bisect.bisect_left(bounds, age)` за O(log k); возраст, равный границе, попадает в нижнюю группу;
- все респонденты сортируются **один раз** по ключу `(-age, name)`: так люди идут по убыванию возраста, а при равном возрасте по ФИО;
- при таком порядке номер группы не возрастает, поэтому `itertools.groupby` по номеру группы сразу выдаёт группы от старшей к младшей, пустые группы не появляются;
- итоговая сложность O(n log n), без словарей и повторных сортировок.

## 5. Принятые решения

| Место условия | Решение |
|---|---|
| «Хотя бы половина фильмов совпадает» | по множествам разных id: история отобрана, если `2 * common >= len(watched)` |
| Где считать просмотры в шаге 3 | буквально по условию: по всем историям сервиса, а не только по отобранным |
| Повторы id в истории (`2,2,2`) | каждое вхождение считается отдельным просмотром |
| Несколько фильмов с равным счётом | выбирается наименьший id (условие разрешает любой, нужна детерминированность) |
| Вес в режиме `--weighted` | `w(h) = common(h) / len(watched)`; оценка фильма — сумма `w(h)` по всем его просмотрам |
| Кандидатов нет | выводится «Рекомендаций нет», код 0 |
| Возраст, равный границе | входит в нижнюю группу: 18 → `0-18` |
| Равный возраст в группе | ФИО сравниваются как строки Python, по кодам символов, без `locale` |
| Плохая строка респондента | предупреждение в stderr с номером строки, строка пропускается |

## 6. Ограничения

- ФИО сортируются по кодам символов Unicode, поэтому `Ё` стоит раньше `А`; алфавитный порядок с учётом `ё` потребовал бы `locale` или собственной таблицы.
- Данные задачи 1 целиком загружаются в память; для очень большой истории понадобился бы потоковый подсчёт или индекс.
- Приложение задачи 1 читает пути `data/movies.txt` и `data/history.txt` относительно текущей папки и запускается из корня проекта.
